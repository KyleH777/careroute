  <name>Task 2: Deploy job in ci.yml</name>
  <action>
- Top-level concurrency: `cancel-in-progress: ${{ github.ref != 'refs/heads/main' }}`.
- Add `workflow_dispatch` with inputs `image_tag` (optional; default = this commit's sha- tag) and `simulate_migration_failure` (boolean, default false).
- `image` job: unchanged, but expose output `tag` = `sha-${GITHUB_SHA::7}` (must match metadata-action type=sha).
- New job `deploy`: `needs: image`; `if: github.ref == 'refs/heads/main'` (push or dispatch); `environment: production`; `concurrency: { group: deploy-production, cancel-in-progress: false }`; `permissions: { id-token: write, contents: read }`; env `ARM_USE_OIDC=true`, `ARM_CLIENT_ID/ARM_TENANT_ID/ARM_SUBSCRIPTION_ID` from `vars`, `TF_VAR_operator_object_id` from vars, `TF_IN_AUTOMATION=1`, `TF_INPUT=0`.
  Steps:
  1. checkout; `azure/login@v2` (client-id/tenant-id/subscription-id; OIDC); `hashicorp/setup-terraform@v3` (pinned version, `terraform_wrapper: false`).
  2. `terraform init -backend-config=backend.hcl` in infra.
  3. Resolve NEW (the input or needs.image.outputs.tag) and CURRENT_APP (`terraform output -raw app_image`). Echo both (images are not secret).
  4. **Stage 1**: `terraform apply -auto-approve -var migrate_image=ghcr.io/kyleh777/careroute:$NEW -var app_image=$CURRENT_APP > "$RUNNER_TEMP/stage1.log" 2>&1`; on failure print only lines matching `Error|error:` (with 5 lines of context) and exit 1. On success print only `grep -E '^(Apply complete|.*: (Creation|Modifications|Destruction) complete)'`.
  5. **Migrate**: if `simulate_migration_failure`, start the job with an override (`--image` NEW, `--env-vars` MIGRATE_ENV per AZURE.md, `--command python --args "-craise SystemExit('drill: simulated migration failure')"`); else a plain `az containerapp job start -n careroute-migrate`. Record the API's revision list (names) before. Poll `job execution show` until Succeeded/Failed (timeout 12 min). Print the execution's job logs (Alembic output only; no secrets are logged). Failed or timeout → `::error::` and exit 1.
  6. **Stage 2**: the same pattern with `-var app_image=...:$NEW`.
  7. **Smoke**: API URL from `terraform output -raw api_url`; `/ready` 200 with up to 10 retries; assert `az containerapp show ... image` == NEW and `terraform output -raw migrate_image` == NEW; print the active revision name. Stage 1/2 logs stay in RUNNER_TEMP (never uploaded).
- No `actions/upload-artifact` anywhere in the deploy job; no `terraform plan -out`; no `terraform show`.
  </action>
  <verify>actionlint if available (`docker run --rm -v "$PWD":/repo -w /repo rhysd/actionlint:latest`), else a YAML parse; `grep -n "upload-artifact\|-out=\|terraform show" .github/workflows/ci.yml` shows nothing in the deploy job</verify>
  <done>The workflow encodes the ordered deploy.</done>
