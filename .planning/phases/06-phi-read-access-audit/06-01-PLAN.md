<objective>
Create the durable, append-only access-audit table that every later plan writes to and queries.

Purpose: CONTEXT.md locks a Postgres table as the durable audit record, append-only for the API role, holding both read rows (AUDIT-01) and provider-assignment rows (AUDIT-02). The hard part (RESEARCH Pitfall 1) is that `scripts/db_roles.py` default privileges and its blanket `GRANT ... ON ALL TABLES` would silently give the app UPDATE/DELETE. This plan closes that in both the migration and db_roles.py and proves it with a contract test.
Output: `RecordAccess` model, Alembic migration, db_roles.py revoke, updated privilege contract, table tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API process -> Postgres (app role) | A compromised API holds the app role credentials |
| db_roles bootstrap (admin) -> schema | Re-runs on every compose up, restore and rotation; can re-grant privileges |
| Operator env (APP_DB_ROLE) -> migration DDL | Role name interpolated into REVOKE |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering / Repudiation | record_access via app role | mitigate | REVOKE UPDATE, DELETE, TRUNCATE in the migration and in db_roles.py after the blanket GRANT; contract tests assert has_table_privilege and real statements raise InsufficientPrivilege, including after a bootstrap re-run |
| T-06-02 | Tampering | db_roles.py re-run re-granting UPDATE/DELETE | mitigate | APPEND_ONLY_TABLES revoke runs on every bootstrap, guarded by to_regclass; test_append_only_survives_db_roles_rerun |
| T-06-03 | Tampering (injection) | migration REVOKE role name | mitigate | APP_DB_ROLE validated against ^[a-z_][a-z0-9_]{0,62}$ and double-quoted; existence checked with a bound parameter |
| T-06-04 | Repudiation | audit rows lost when a referral/patient is deleted or seed --reset runs | mitigate | No foreign keys; seed.reset does not truncate record_access; tests test_rows_survive_referral_delete and test_seed_reset_keeps_record_access |
